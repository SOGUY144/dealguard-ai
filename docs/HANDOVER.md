## 1. ระบบนี้คืออะไร (30 วินาที)

ผู้ช่วย AI ต่อราคาแทนร้านขายส่ง SME ("ร้านเฮียชัยโมบาย" ขายสายชาร์จ) ลูกค้าพิมพ์หรือพูด เช่น "ขอ 125 ได้ไหม 1,000 ชิ้น" แล้ว AI **ไม่ลดราคาฟรี** แต่เสนอ 3 ทางแลกเปลี่ยนที่ร้านยังได้กำไร:

| ข้อ | lever | ตัวอย่าง |
|---|---|---|
| A ซื้อเยอะ | ขั้นราคาตามจำนวน | 1,500 ชิ้น × ฿130 |
| B จ่ายสด | ลดเพราะไม่ใช้เครดิต | 1,000 × ฿135 |
| C รับของแถม | ระบายของค้างสต๊อก | 1,000 × ฿145 + หัวชาร์จ 200 ชิ้น |

ลูกค้ากดยืนยัน → เกิดออเดอร์ → หน้าเถ้าแก่เห็น "กำไรที่รักษาไว้" เด้งขึ้นทันที · เรื่องคืนเงิน/ร้องเรียน/ดีลใหญ่เกิน/ลูกค้าขอคุยกับคน → ส่งให้เถ้าแก่ตอบเอง

## 3. เริ่มทำงานบนเครื่อง

```bash
git clone https://github.com/SOGUY144/dealguard-ai.git
cd dealguard-ai
npm install
```

1. คัดลอก `.env.example` เป็น `.env.local` แล้ว **ขอค่าคีย์จากเจ้าของโปรเจกต์ทางช่องทางส่วนตัว** (ห้ามส่งในแชตกลุ่ม/ห้าม commit)

   - `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`, `ELEVENLABS_MODEL_ID` (eleven_v4_turbo)
   - `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` (**ห้ามใส่ `NEXT_PUBLIC_` หน้าตัวนี้เด็ดขาด**)
   - `SITE_URL` (เครื่องตัวเอง = `http://localhost:3000`)
2. `npm run check-keys` — ยิง GPT + สร้างเสียงไทย 1 ประโยค ถ้าผ่านแปลว่าคีย์ครบ
3. `npm run dev` → http://localhost:3000
4. บัญชีเดโมอยู่ในไฟล์ `.demo-accounts.local.md` (ไม่อยู่ใน git — ขอจากเจ้าของ) **ห้ามพิมพ์รหัสลงแชต/เอกสาร**

## 5. ระบบทำงานยังไง

### 5.1 สามชั้น (SKILL §6.1 — ห้ามรวมชั้น)

```
ข้อความลูกค้า
   │
   ▼  Layer 1 — แยกเจตนา (lib/ai/intent.ts)
   │    GPT structured output → Intent JSON · ช้า/ล่ม → regex สำรอง (lib/ai/fallback-intent.ts)
   │    คืนเงิน/ร้องเรียนจับด้วยกฎของเราเสมอ (GPT อ่านพลาดก็ไม่หลุด)
   ▼  Layer 2 — Deal Engine (lib/deal-engine/) ฟังก์ชันล้วน ไม่มี I/O ไม่มี LLM
   │    คิดข้อเสนอ A/B/C · Floor Guard · นับรอบต่ำกว่าพื้น/หลอกระบบ · ตัดสินว่าต้องส่งเถ้าแก่ไหม
   ▼  Layer 3 — ข้อความตอบ (lib/chat/replies.ts = template, lib/ai/responder.ts + openai.ts = GPT เรียบเรียง)
        GPT ได้แค่ตัวเลขที่ engine คิดแล้ว → ตัวตรวจ (lib/ai/validator.ts) เช็กทุกตัวเลข/คำสัญญา → ไม่ผ่านใช้ template
        ลูกค้าพูดมา → ElevenLabs อ่านเป็นเสียง (lib/voice/) · เสียงล่ม → ตอบเป็นข้อความ
```

### 5.2 ข้อความหนึ่งข้อความเดินทางยังไง

1. หน้าแชต (`components/chat/chat-screen.tsx` + `use-chat-session.ts`) ส่ง `POST /api/chat` (`app/api/chat/route.ts`) — action มี `pick_product` / `send` / `confirm_offer` / `talk_to_human` (`select_offer` เกิดในหน้าจออย่างเดียว)
2. route เช็กล็อกอิน + rate limit แล้วเรียก `handleAction` ใน `lib/chat-server/pipeline.ts`
3. pipeline: โหลดแชต → ถ้าโหมด `human` เก็บข้อความเฉยๆ (AI ไม่ตอบ) → Layer 1 → Deal Engine → บันทึกตัวนับแบบ compare-and-set → Layer 3 → เสียง (ถ้าพูดมา) → บันทึกข้อความ + ข้อเสนอ (`offers` table) → คืน `ChatView`
4. ยืนยันข้อเสนอ: server หาข้อเสนอจากฐานข้อมูลเอง (**ไม่รับตัวเลขจาก browser**) ตรวจซ้ำว่ายังใช้ได้ (อายุ 24 ชม., ไม่ต่ำกว่าพื้นใหม่, ของแถมยังเปิด, ไม่เกินเกณฑ์) แล้วเรียก RPC `place_order` (ออเดอร์ + หักสต๊อกของแถมในคำสั่งเดียว)
5. Realtime (`lib/supabase/live.ts` + `components/live/use-live-updates.ts`) ส่งข้อความใหม่ให้หน้าลูกค้าและหน้าเถ้าแก่ · หลุด → ดึงทุก 10 วินาที

### 5.4 ฐานข้อมูล

ตาราง: `merchants` (ร้านเดียว + คำตอบให้ลูกค้า `delivery_info`/`stock_info`) · `profiles` (role `owner`/`buyer`) · `products` · `dead_stock` (ของแถม) · `chats` (โหมด `ai`/`human`) · `chat_negotiation` (ตัวนับ — ลูกค้าอ่านไม่ได้ กันเดาราคาพื้น) · `messages` · `offers` · `offer_economics` (กำไร — ลูกค้าอ่านไม่ได้) · `orders` · `escalations` · ตารางนับ rate limit

RPC ที่ใช้ (เรียกได้เฉพาะ service role): `place_order`, `save_product_settings`, `import_products`, `hit_rate_limit`

RLS: ลูกค้าอ่านได้แค่แชต/ข้อความ/ข้อเสนอ/ออเดอร์ของตัวเอง · ข้อมูลสินค้าที่ลูกค้าเห็นผ่าน API ที่ตัดต้นทุน/ราคาพื้นออก (`PublicProduct`) · เถ้าแก่อ่านได้ทุกอย่าง · **การเขียนทั้งหมดทำจาก server** หลังเช็กสิทธิ์ · ฐานข้อมูลมี check constraint ซ้ำกับโค้ด (เช่น ขั้นราคาต้องอยู่ระหว่างพื้นกับราคาขาย) กันกรณีข้ามโค้ด

เพิ่ม/แก้ schema: เขียน `supabase/migrations/2026MMDD0000NN_ชื่อ.sql` ใหม่ → `npm run db:migrate` (กระทบเว็บจริง) → แก้ `supabase-store.ts` / seed / reset-demo ให้ครบ → เขียน test ใน `tests/db/` → **รัน migration ก่อน push โค้ด**

## 7. กฎเหล็ก — ห้ามพัง

1. **ตัวเลขราคา/ยอดรวม/จำนวน มาจาก Deal Engine เท่านั้น** — GPT ห้ามคิด · ข้อความ GPT ต้องผ่าน `validator.ts` (เช็กตัวเลขทีละข้อเสนอ + คำต้องห้าม เช่น ฟรี ส่ง ประกัน คืนเงิน ลดเพิ่ม) ไม่ผ่าน → template
2. **ไม่มีข้อเสนอไหนต่ำกว่าราคาพื้น** (Floor Guard assert ก่อนส่ง + DB constraint) · **ไม่ลดฟรี** — ราคาต่ำกว่าราคาขายต้องมีเงื่อนไขแลกเสมอ
3. **ต้นทุน / ราคาพื้น / กำไร ห้ามไปถึง browser ของลูกค้า** — ไฟล์ที่มีข้อมูลพวกนี้ใส่ `import "server-only"` · ESLint กันไม่ให้หน้าลูกค้า import · เช็กด้วยการค้นไฟล์ใน `.next/static` หลัง build
4. **`SUPABASE_SERVICE_ROLE_KEY` อยู่ฝั่ง server เท่านั้น** ห้ามมี `NEXT_PUBLIC_`
5. **ยืนยันออเดอร์ด้วย id ของข้อเสนอในฐานข้อมูล** ไม่รับราคาจาก browser
6. **เรื่องคืนเงิน/ร้องเรียน/หลอกระบบต้องถึงเถ้าแก่เสมอ** (เงื่อนไข 3 ข้อในหน้าสินค้าติ๊กไว้และปิดไม่ได้ — ตั้งใจ ตาม SKILL §6.8)
7. **คำตอบเรื่องส่งของ/สต๊อก = ข้อความที่เถ้าแก่กรอกตรงตัว** ไม่ผ่าน LLM (กัน AI แต่งคำสัญญา)
8. ข้อความใน `[วงเล็บเหลี่ยม]` ของดีไซน์คือ placeholder ห้ามแต่งเอง · ข้อความที่แต่งเพิ่มต้องจดใน PLAN ให้ทีมตรวจ

## 9. ต่อยอดเรื่องที่ไม่มีใน SKILL — ต้องแก้ตรงไหน

ทุกข้อ: เขียน test ที่ล้มก่อน (TDD) → แก้ → `npm test` + `tsc` + `eslint` → ถ้าแตะฐานข้อมูลเพิ่ม `tests/db/` → ลองบน localhost

**เพิ่มเรื่องคำถามทั่วไป** (เช่น "มีใบกำกับภาษีไหม")
`lib/ai/info-topics.ts` เพิ่ม topic + regex → `lib/chat/replies.ts` ฟังก์ชัน `infoAnswer` → ถ้าต้องให้เถ้าแก่กรอกคำตอบ: migration เพิ่มคอลัมน์ใน `merchants` + `ShopAnswers` (`lib/deal-engine/types.ts`) + `supabase-store.ts` + `lib/owner/shop-answers*.ts` + `components/owner/shop-answers-panel.tsx` + seed/reset

**เพิ่มทางแลกเปลี่ยนใหม่ (lever)** เช่น "รับของเองที่ร้าน ลด ฿2"
`lib/deal-engine/offers.ts` (คิดราคา + เงื่อนไข) → `types.ts` (lever ใหม่) → `margin.ts` (กำไร) → `guard.ts` ยังต้องผ่าน → `validator.ts` (ให้ตัวเลขของข้อใหม่ผ่าน) → `openai.ts` (คำอธิบายให้ GPT) → การ์ดข้อเสนอ `components/chat/offer-list.tsx` → ค่าตั้งในหน้าสินค้า (migration + `product-settings`) · ระวัง: ข้อ A/B/C ถูกอ้างในดีไซน์และสคริปต์เดโม

**เพิ่มช่องตั้งค่าร้าน/สินค้า**
migration ใหม่ → `supabase-store.ts` (โหลดเข้า `MerchantConfig`) → `lib/owner/products.ts` / RPC `save_product_settings` (ถ้าเป็นช่องในฟอร์มเดิม ต้อง `create or replace` function ใน migration ใหม่) → หน้าจอ `components/owner/product-settings.tsx` → `scripts/seed.ts` + `scripts/reset-demo.ts` + `merchant.json`

**เพิ่มหน้าใหม่**
`app/<path>/page.tsx` · อ่าน session ได้เฉพาะใน `<Suspense>` (Cache Components) · หน้าเถ้าแก่ต้องเรียก `requireOwner()` · หน้าที่เปิดได้ไม่ต้องล็อกอิน เพิ่มใน `PUBLIC_PATHS` ของ `lib/auth/routes.ts` · Next 16 เก็บหน้าที่ออกไปไว้ใน `<Activity>` (state ค้าง, effect ถูกปิด/เปิดใหม่) — ไมค์/เสียง/ตัวจับเวลาต้องปิดตอน cleanup

**เปลี่ยนข้อความที่ AI พูด**
template: `lib/chat/replies.ts` · ข้อความ GPT: คำสั่งใน `lib/ai/openai.ts` (`WRITER_INSTRUCTIONS`) + กฎใน `validator.ts` · ทุกครั้งที่แก้ ลองกับ GPT จริงหลายประโยค (PLAN มีวิธี probe) เพราะ test ใช้ GPT ปลอม

**เปลี่ยนเสียง / โมเดล**: ตั้งใน env (`ELEVENLABS_VOICE_ID`, `OPENAI_MODEL` ฯลฯ) ทั้งใน `.env.local` และ Vercel

**ต่อช่องทางอื่น (LINE OA ฯลฯ)**: `handleAction` ใน pipeline ไม่ผูกกับหน้าเว็บ — webhook ใหม่แปลงข้อความเข้าเป็น `ChatAction` แล้วแปลง `ChatView` กลับเป็นข้อความ/ปุ่มของช่องทางนั้น (ต้องคิดเรื่องตัวตนลูกค้า เพราะตอนนี้ผูกกับบัญชีอีเมล)
